# Workflow 外部记忆截止线

本笔记解决了 Workflow 中 Aleph 风格外部记忆的 v0.9.0 截止线。它是一个设计边界，而非运行时实现。

## 决策

外部记忆对于 v0.9.0 应保持可选和显式。正常的 CodeWhale 操作不得依赖它，Workflow 不得为长时间运行静默启用它。

对于 v0.9.0，外部记忆只能以以下形式出现：

- 一个显式的 workflow 节点，其输入、输出、范围和权限在类型化的 Workflow IR 中可见；
- 一个可选的插件或技能支持的工具，由用户有意启用；
- 一个文档化的实验，其状态可以被检查、清除和导出。

它不应是一个隐藏的上下文基底、仓库搜索的替代品，或每个 workflow 运行的默认后备存储。

## 层次边界

外部记忆与现有的记忆和回放层次分离：

| 层次 | 范围 | v0.9.0 规则 |
| --- | --- | --- |
| 用户记忆 | 小而持久的用户偏好和事实，通过 `/memory` 呈现 | 选择加入，用户拥有，非 workflow 证据 |
| 仓库搜索 / codemap | 派生的仓库结构和搜索结果 | 可从工作区重建；非记忆日志 |
| ARMH/RLM memo | 会话内工作记忆和精确上下文记忆化 | 可见的命中/未命中遥测；非持久回放证据 |
| TraceStore | 记录的 workflow、分支、叶子和控制结果 | 确定性回放的来源；回放期间无实时模型调用 |
| 缓存主覆盖层 | 经过审查和回放后晋升的经验教训 | 可检查且可逆；绝不变更 Git main |
| 外部记忆 | 位于正常上下文之外的大型本地或插件支持数据 | 仅显式节点/插件；需要可见状态和 clear/export |

## 可见性要求

任何未来的外部记忆实现必须显示：

- 何时处于活动状态；
- 哪个 workflow 节点或插件拥有它；
- 其状态存储在哪里；
- 它可以读取什么仓库或运行范围；
- 它是否包含在回放、导出或晋升证据中；
- 如何检查、清除、固定和导出它。

UI 应将其视为活动上下文层，而非不可见的模型直觉。如果一个运行无法解释为什么某个事实来自外部记忆，则该功能尚未准备好默认使用。

## 权限和隐私

外部记忆必须继承最严格的相关范围：

- 未经显式批准，不得跨越仓库/工作区边界；
- 项目本地配置不得静默启用广泛的外部记忆读取；
- 回放必须将外部记忆输入记录为证据，或将回放标记为不可用/偏离；
- 导出必须使外部记忆引用可见，默认情况下不转储私有原始状态。

## 推迟的工作

以下内容保持在 v0.9.0 截止线范围之外：

- 对所有 Workflow 运行默认开启 Aleph 风格记忆；
- 从外部记忆自动晋升到缓存主覆盖层；
- 隐藏在普通 prompt 后面的检索；
- 托管或共享的外部记忆服务；
- 将外部记忆视为 TraceStore 回放的替代品。

未来实现应从只读类型化 workflow 节点和模拟回放夹具开始，然后再添加任何插件支持或实时检索路径。
