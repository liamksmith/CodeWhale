## 八、语言强化（Bookend 模式）（第 691–871 行）

这是 CodeWhale 中一个非常巧妙的设计，解决了一个实际问题：

### 问题
用户设了 `lang: zh-Hans`，但随着会话中累积大量英文代码、错误日志、文件内容，模型会**因注意力机制的"近因偏差"**（recency bias）逐渐漂移回英文思考——忽略最开头那一条"请用中文思考"的指令。

### 解决：Bookend 模式
在系统提示词的**开头和结尾**各放一条母语指令：

```rust
pub(crate) fn locale_reinforcement_preamble(locale_tag: &str) -> Option<&'static str> {
    match locale_tag {
        "zh-Hans" | "zh-CN" | "zh" => Some(effective_locale_preamble_zh_hans()),
        "ja" | "ja-JP" => Some(effective_locale_preamble_ja()),
        ...
        _ => None,  // en 和其他语言返回 None，不改变现有行为
    }
}
```
- **前言（preamble）** — 放在提示词最开头，用母语告诉模型"你必须用 X 语言思考"。
- **后记（closer）** — 放在提示词最末尾（紧挨用户消息之前），利用注意力最大权重位置重申语言规则。

```rust
const LOCALE_PREAMBLE_ZH_HANS: &str = "## 语言要求\n\n\
    你正在 codewhale 中运行。无论任务上下文是英文，...\
    你都必须用简体中文进行 reasoning_content 和最终回复。...";
```

```rust
const LOCALE_CLOSER_ZH_HANS: &str = "## 语言再次提醒\n\n\
    **重要：你的 reasoning_content 和最终回复必须保持简体中文。**\
    无论你在这次会话中读到了多少英文代码...";
```

四种支持的语言：**简体中文、日语、巴西葡萄牙语、越南语**。

## 整体总结

| 职责 | 说明 |
|------|------|
| **编译时常量加载** | 用 `include_str!` 在编译时嵌入所有 `.md` 提示词文件 |
| **分层组合** | 从静态到易变层层叠加，保证前缀缓存命中率 |
| **Embedder 覆盖** | 通过 `OnceLock` 允许一次性替换提示词，防止竞态 |
| **语言 Bookend** | 首尾母语指令防止模型受英文上下文影响漂移 |
| **Config 目录覆盖** | 用户可自定义宪法但需要环境变量 opt-in（安全门控） |
| **完整上下文组装** | 12 个层次按序叠加，从模式提示词到交接文件 |
| **前缀缓存意识** | 易变内容（交接、记忆、目标）放最后，静态前缀跨会话复用 |

这个文件是 CodeWhale 的**提示词工程核心**——它把行为规范（宪法）、模式差异、语言策略、用户配置、会话上下文等所有因素组合成最终发送给 LLM 的系统提示词。
